# LLMxCPG 与 ReAct 简短技术笔记

## LLMxCPG

需要从论文原文与开源实现进一步逐项复核的结论：其核心可复用边界是把漏洞语义、目标代码/CPG上下文组织成模型输入，让模型产出受约束的 CPGQL，再把查询交给 Joern 并消费结果。第一阶段可直接复用的是“查询输出应机器可解析、生成与执行分离、失败反馈给决策层”的工程思想；不能照搬一次性生成查询的流程。本项目第二阶段必须将当前假设、前置条件集合、查询历史、上一轮 Observation、预算和允许动作一并输入 Think 节点，使其成为跨轮迭代选择。

当前仓库没有把未经论文/代码核验的提示词格式、重试次数或错误恢复策略写成事实。待获得稳定网络或固定论文版本后，应补齐准确页码、commit SHA 和差异表。

## ReAct

每轮读取：当前漏洞假设、待验证条件、历史动作与观察、迭代预算；写回：所选查询、原始 Observation、T1证据引用、条件裁定和终止原因。失败分三类：执行失败/超时不等于证伪，格式不可解析不等于证伪，成功空结果在没有封闭世界保证时也只能 unknown。终止条件为 confirmed、refuted、查询计划耗尽、关键条件 unresolved、达到最大轮次。

本研究与通用 ReAct 的关键区别是权限分离：LLM 未来只负责查询决策和 T2/T3 归纳；T1、前置条件裁定、状态迁移始终由确定性代码负责。
